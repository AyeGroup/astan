# سرویس گفتارسازی فارسی — راهنمای هوشمند موزه

سرویس TTS سلف‌هاست بر پایهٔ Piper که علاوه بر صوت، **تایم‌لاین واج** برمی‌گرداند
تا لب‌سینک آواتار از روی واج واقعی رانده شود، نه از روی انرژی صوت.

## چرا سمت سرور، نه مرورگر

دو محدودیت که این تصمیم را اجباری می‌کند:

۱. خروجی `speechSynthesis` مرورگر قابل اتصال به WebAudio نیست، پس هیچ سیگنالی
   برای تحلیل باقی نمی‌ماند و لب‌سینک به حدس مصنوعی تنزل می‌کند.
۲. پوشش صدای فارسی در مرورگرها ضعیف است؛ روی iOS عملاً وجود ندارد.

## اجرا

```bash
pip install -r requirements.txt

# ۱. دریافت مدل صدا — جایی که huggingface.co در دسترس است
./scripts/fetch_voices.sh ./voices

# ۲. اجرا
TTS_BACKEND=piper TTS_VOICES_DIR=./voices uvicorn app.main:app --port 8080
```

یا با داکر: `docker compose up -d` (پوشهٔ `voices/` را mount می‌کند).

## دو بک‌اند، هیچ‌کدام ساختگی

| بک‌اند | کیفیت صدا | نیاز به دانلود |
|---|---|---|
| `piper` | طبیعی | مدل صدا از HuggingFace |
| `espeak` | رباتیک ولی قابل فهم | **هیچ** — بستهٔ PyPI با دادهٔ خودش |

`auto` اول Piper را امتحان می‌کند و اگر مدلی نبود به espeak برمی‌گردد.

این فقط یک راه‌حل تست نیست. مدل Piper روی HuggingFace است و شبکهٔ یک موزه ممکن
است اصلاً به آن نرسد — یعنی یک دانلود تبدیل به مانع استقرار کل پلتفرم می‌شود.
با espeak، موزه همان روزی که سرویس را نصب می‌کند راهنما را سرتاسر اجرا می‌کند و
بعداً صدای Piper را بدون هیچ تغییر دیگری جایگزین می‌کند.

espeak هم موقعیت صوتی واقعی هر واج را گزارش می‌دهد، پس تایم‌لاین این بک‌اند هم
**اندازه‌گیری‌شده** است نه تخمینی — همان کیفیت هم‌ترازی که alignment های Piper
می‌دهند.

`/health` با `quality` و `natural_voice` مشخص می‌کند اپراتور کدام را دارد.

## API

| مسیر | کار |
|---|---|
| `POST /speak` | `{text, voice?, lang?, rate?, format?}` → پیش‌فرض `audio/wav`؛ با `format: "json"` صوت base64 به‌همراه تایم‌لاین واج |
| `POST /prerender` | `{texts: [...]}` گرم‌کردن کش برای پاسخ‌های پرتکرار |
| `GET /voices` | صداهای موجود و نام‌های مستعار |
| `GET /health` | آمادگی، بک‌اند فعال، آمار کش |

نمونهٔ خروجی `format: "json"`:

```json
{
  "audio": "UklGRi...",
  "mime": "audio/wav",
  "normalized": "مامان بابا به موزه می‌آیند.",
  "duration": 2.623,
  "timeline": [
    {"t": 0.0,   "o": 0.02, "s": 0.42},
    {"t": 0.062, "o": 0.95, "s": 0.42},
    {"t": 0.177, "o": 0.02, "s": 0.42}
  ]
}
```

`o` بازشدگی دهان و `s` کشیدگی افقی لب، هر دو در بازهٔ ۰ تا ۱.
دنبالهٔ بالا «مامان» است: م بسته، ا باز، م بسته — همان چیزی که روش انرژی‌محور
هرگز تولید نمی‌کند، چون انرژی صوت روی م/ب/پ بالا می‌ماند و دهان باز می‌ماند.

## نرمال‌سازی متن

هر قاعده روی یک شکست **اندازه‌گیری‌شده** در واج‌نگار espeak کار می‌کند:

| ورودی خام | بدون نرمال‌سازی خوانده می‌شود |
|---|---|
| `**کاسهٔ صفوی**` | «ستاره‌ستاره کاسهٔ صفوی ستاره‌ستاره» |
| `## دورهٔ صفوی` | «هَش‌هَش دورهٔ صفوی» |
| `است [۱] و لعاب دارد` | «است **یک** و لعاب دارد» |
| `ساعت 9:30` | «ساعت نه **دو نقطه** سی» |
| `۱۴۰۳/۵/۲` | «... **اسلش** پنج **اسلش** دو» |
| `museum.example.com` | «میوزیم نقطه اگزامپل نقطه کام» |
| `😀` | «خنده» |

و آنچه عمداً **انجام نمی‌شود**: تبدیل عدد به حرف. espeak خودش `۴۰۰` را
«چهارصد» می‌خواند؛ بازنویسی‌اش فقط یک پیاده‌سازی دوم و بدتر اضافه می‌کرد.

یک نکتهٔ ظریف که تست‌ها گرفتند: همزهٔ `ٔ` در «هٔ» نباید جزو حرکات حذف شود،
چون نشانهٔ اضافه است و «موزهٔ ملی» را به «موزه ملی» تبدیل می‌کند.

## کش

کلید کش از متنِ **نرمال‌شده** ساخته می‌شود، پس `**متن**` و `متن` یک ورودی
حساب می‌شوند. در موزه بیشتر پرسش‌ها تکراری‌اند، بنابراین `/prerender` روی
پرسش‌های پرتکرار هر اثر عملاً تأخیر سنتز را حذف می‌کند.

## تست

```bash
python3 -m pytest tests/ -q
```

سه لایه: نرمال‌ساز، رگرسیون واج‌نگاری (اثبات اینکه خروجی espeak واقعاً بهتر
می‌شود، نه فقط رشته تمیزتر)، و قرارداد HTTP.

## پیکربندی

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `TTS_BACKEND` | `auto` | `piper` \| `dev` \| `auto` |
| `TTS_VOICES_DIR` | `./voices` | محل فایل‌های `.onnx` |
| `TTS_DEFAULT_VOICE` | `fa_IR-amir-medium` | صدای پیش‌فرض |
| `TTS_CACHE_DIR` | `./cache` | کش دیسک |
| `TTS_CACHE_MAX_MB` | `2048` | سقف کش، تخلیه به روش LRU |
| `TTS_CORS` | `*` | مبدأهای مجاز |
| `TTS_LENGTH_SCALE` | `1.0` | آهنگ گفتار؛ بزرگ‌تر یعنی کندتر |

## اتصال به فرانت‌اند

```html
<script>
  window.MUSEUM_CONFIG = {
    tts: { mode: 'server', endpoint: 'https://tts.example.com/speak' }
  };
</script>
```

`app/js/tts.js` خودش `format: "json"` درخواست می‌دهد و اگر سرور فقط WAV بدهد،
بی‌صدا به لب‌سینک انرژی‌محور برمی‌گردد.
