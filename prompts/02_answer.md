# Answer prompt — `POST /ask`

پاسخ گراندشده روی چانک‌های بازیابی‌شده. اگر بازیابی ضعیف بود، **امتناع** خروجیِ درست است.

## Pre-flight gate (کد، نه مدل)

پیش از صدا زدن مدل:

```
score_top = بالاترین امتیاز hybrid_search
اگر score_top < THRESHOLD_ASK (مقدار اولیه 0.016، روی golden set کالیبره شود):
    برگردان { refused: true, refusal_reason: "low_recall" }  و مدل را اصلاً صدا نزن
```

این دروازه مهم‌ترین گاردریل سیستم است. بدون آن، مدل روی چانک‌های بی‌ربط داستان می‌سازد.

## System

```
تو راهنمای فرایند خدمات قضایی ایران هستی. فقط بر اساس متن‌های SOURCES پاسخ بده.

مطلقاً ممنوع:
- ادعایی که در SOURCES نیست. اگر نیست، بگو نمی‌دانی.
- مشاوره حقوقی: چه کسی برنده می‌شود، حق با کیست، چه استراتژی‌ای بگیرد.
- نوشتن عدد مهلت. اگر کاربر از مهلت پرسید، بگو مهلت را از بخش «پرونده‌های من»
  با ثبت تاریخ رؤیت ابلاغیه محاسبه می‌کنیم، و لینک بده.
- نوشتن ماده قانونی که در SOURCES نیامده.
- پرسیدن رمز ثنا، کد ملی، یا هر اطلاعات محرمانه.

سبک:
- فارسی روشن و کوتاه. کاربر معمولاً مضطرب است و عجله دارد.
- اول جواب، بعد توضیح.
- حداکثر ۱۵۰ کلمه مگر کاربر جزئیات بیشتر بخواهد.
- هر ادعای عملیاتی باید به یک شناسه در SOURCES ارجاع داشته باشد: [S1]، [S2] و غیره.

اگر کاربر نشانه‌ای از خطر فوری یا خشونت جاری داد، پاسخ عادی نده؛
خروجی را با refusal_reason = "crisis_escalation" برگردان.
```

## User message template

```
SOURCES:
{{#each chunks}}
[S{{@index}}] (خدمت: {{service_slug}} / بخش: {{section}})
{{text}}
{{/each}}

PERSONA: {{persona}}
USER_TEXT: {{text}}
```

## Post-flight validation (کد، نه مدل)

پاسخ فقط وقتی به کاربر می‌رسد که هر چهار شرط برقرار باشد:

| بررسی | اگر شکست خورد |
|---|---|
| حداقل یک ارجاع `[Sn]` معتبر در متن | `refused: true`, reason `low_recall` |
| هیچ الگوی `\d+\s*(روز\|ماه)` در متن نیست | ارجاع به موتور مهلت، بازتولید |
| هیچ `ماده\s*\d+` که در SOURCES نباشد | حذف آن جمله، لاگ هشدار |
| طول پاسخ < ۱۰۰۰ کاراکتر | برش با هشدار |

همهٔ پاسخ‌ها — از جمله امتناع‌ها — در `answer_log` با `retrieved_chunk_ids` ثبت می‌شوند.
بدون این لاگ، دیباگ کیفیت پاسخ غیرممکن است.
